# MISSION.md format

`MISSION.md` sits at the root of the workspace. It records why the user learns
the topic. Each choice of what to teach next traces back to it.

## Template

```md
# Mission: {Topic}

## Why
{One to three sentences. The real goal, and what changes for the user when
they have the skill.}

## Success looks like
- {One thing the user can do, and you can observe}

## Constraints
- {Time, budget, other duties, and how the user likes to learn}

## Out of scope
- {Near topics that the user does not want now}
```

## Rules

- **One mission for each workspace.** Two unrelated goals need two workspaces.
- **Concrete goals only.** "Run a half marathon by October" works. "Get
  fitter" does not.
- **Push back on a vague answer.** Interview the user before you write. A bad
  mission is worse than none.
- **Update it when the goal moves.** A stale mission steers wrong. Confirm
  with the user first, then write a learning record.
- **Keep it on one screen.** A longer file is a plan, not a compass.
